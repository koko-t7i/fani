# 架构修复计划

目标：修复长任务互斥、预览与执行不一致、多仓库错误传播问题，并收紧存储事务和编排职责边界。

基线：`e18bae7531fc2456b34c3c0802e45f4a356f593c`。任务分支：`fix/architecture-boundaries`。

## 工作包与依赖

| 工作包 | 责任 | 实施范围 | 验收 |
| --- | --- | --- | --- |
| A：仓库互斥 | 锁 Agent；主 Agent 集成入口 | 进程持有仓库目录锁；数据库初始化前加锁；保留 SQLite 恢复租约 | 暂停和租约到期不允许接管；退出可恢复；子进程不继承锁 |
| B：共享规划 | 规划 Agent | 抽出解析、匹配、复用、目标冲突的只读规划；预览与执行共用 | Markdown/JSON、零单元、修改/删除/已有目标均一致；预览无模型调用且不修改权威数据库 |
| C：存储边界 | 存储 Agent；主 Agent 集成调用 | 职责接口拆分；必需能力无默认降级；内容与身份同事务；工作与 outbox 同事务 | 注入失败后整体回滚；已有幂等恢复契约继续通过 |
| D：批次错误隔离 | 主 Agent | 仓库循环统一异常边界；先校验选择条件 | 损坏数据库进入报告；后续仓库完成；退出码为 error |
| E：编排与架构测试 | 主 Agent | 拆出发布、人工协调模块；移除文件行数和调用次数要求 | 依赖方向和发布恢复测试通过；允许合理模块拆分 |

A、B、C 在同一已同步基线上并行，按文件和函数区域隔离；D、E 同期实施。集成在 C 的接口稳定后进行，最终验证针对合并后的同一工作区。

## 实施决策

- 保持一个 Rust 包、SQLite 单一状态权威、既有数据库 schema 和 CLI 配置契约。
- 本地 Linux 互斥使用仓库目录 inode 的文件锁，覆盖进程暂停及不同 data_dir。SQLite 租约用于恢复元数据，不能作为允许两个活进程并发的依据。升级时停止旧版本进程。
- 已有 `persist_canonical_file` 原子保存内容、版本和翻译链接；修复聚焦随后身份绑定以及物化工作/outbox 的提交边界。文件、Git、模型调用不进入 SQLite 事务。
- 发布与人工协调拆成应用层模块，保留既有恢复流程及失败注入点，避免同步引入新插件框架或数据库迁移。

## 验证与交付

先运行新增行为回归，再执行架构、SQLite 恢复、文档复用、CLI、Git 发布测试。集成完成后执行格式检查、Clippy、全量 Rust 测试、release 构建和版本入口检查。记录实际结果及未运行的环境相关检查。

验证通过后审查差异，提交到任务分支并创建 PR；合并需要用户明确授权。

## 实施结果

A–E 已完成。共享规划位于 `src/application/sync/planning.rs`；发布和人工协调分别位于 `publication.rs` 与 `reconciliation.rs`。`StateStore` 聚合六组必需能力，并提供原子规范内容/身份提交与物化意图提交。

在统一工作区、Rust 1.85 下完成：

- `cargo test --locked --all-targets`：221 项通过，19 个测试套件；包含 SQLite 恢复、Git 发布、可复现候选和新增回归。
- `cargo clippy --locked --all-targets --all-features -- -D warnings`：通过。
- `cargo fmt --all -- --check`、`git diff --check`：通过。
- `cargo build --locked --release`：通过；`target/release/fani --version` 返回 `fani 0.3.0`。

未在本地运行需要发行工具链与双环境构建的完整 release 可复现性脚本；已运行其相关 Rust 发布契约与候选可复现性测试。

早期多 Agent 同时重建测试二进制时曾出现 Git 子进程启动失败；停止交叉构建后，统一全量测试全部通过。新增 Rust 存储接口需要现有 Rust 实现者适配六个职责 trait；自定义 Agent 的请求/响应协议未变。

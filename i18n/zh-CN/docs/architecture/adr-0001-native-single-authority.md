# ADR-0001：原生 Rust 引擎和单一 SQLite 权威源

- **状态：** 已接受
- **日期：** 2026-08-30
- **决策负责人：** fani 维护者
- **取代：** 记录了实验性外部技能/Python 兼容架构的 [`compatibility-baseline.md`](compatibility-baseline.md) 和 [`rust-sqlite-rewrite.md`](rust-sqlite-rewrite.md)

## 上下文

实验性预发布设计将 fani 所有的状态分散存储在 SQLite 与由外部 Python i18n 技能维护的文件中。运行时操作依赖于 Python、`uv`、用户安装的技能检出副本、JSON/JSONL 协议以及兼容性锁定。规划过程可能会读取可变的工作树内容，而且中断后文件与状态的发布可能出现不一致。

fani 尚未提供兼容性契约。保留这一实验性边界会导致两个权威来源并存，使干净的 CI 执行依赖于用户状态，并妨碍翻译、物化和发布过程的原子化恢复。

## 决定

fani 是一个 Rust 软件包，其中包含一个库和一个二进制文件。依赖关系的方向是：

```text
main -> cli -> application -> domain
                    ^
                    |
                 adapters
```

应用层拥有粗粒度 I/O 端口 `StateStore`、`AgentExecutor`、`Materializer`、`GitPublisher` 和 `CodeHost`。具体的 SQLite、HTTPS 提供程序、进程、文件系统、Git 和 GitHub 适配器仅在最外层的组合根中进行装配。领域层包含纯 Markdown 提取、匹配、受保护语法处理、组装和验证。

运行时权限边界如下：

1. 已解析的 Git 提交是运行所用源字节的权威依据。
2. 一个由 fani 标识的 SQLite 数据库，是文档和单元标识、翻译记忆库、工作尝试、发现、规范内容、恢复意图、租约、发布及拉取请求元数据的唯一 fani 自有权威数据源。
3. 智能体的输出是不受信任的候选文本。智能体在隔离的临时目录中接收有界的类型化工作，绝不会写入代码库或数据库状态。
4. 目标工作树是一个物化投影。与规范字节不一致的情况会被报告为 `HUMAN-EDIT`，并且需要显式执行 `adopt` 或 `discard`。
5. Git 发布从已记录的源提交开始，并使用类型化变更和比较并交换更新。报告和临时协议文件是可替换的证据，而非权威依据。

编号的 SQL 迁移和带版本的提示词已嵌入二进制文件中。实验性 SQLite 架构会被显式重置，而不会进行迁移。任何运行时路径都不会导入旧的 JSON/JSONL 状态、调用外部 i18n 技能、创建与 Python 兼容的锁，也不需要 Python 或 `uv`。

## 后果

### 积极

- 全新克隆构建和 CI 仅需要已声明的 Rust 工具链、锁定文件、Git、`rusqlite` 捆绑的 SQLite 支持、提供商凭据或已配置的自定义 Agent 命令，以及在启用 GitHub 发布时所需的 `gh`。
- 持久化状态转换和发件箱支持幂等恢复，无需重复已完成的智能体工作。
- 纯原生 Markdown 行为可以独立于 SQLite、Git、进程和 GitHub 进行测试。
- 固定源规划和发布可避免可变工作树的竞态，并保留无关的检出状态。

### 成本和限制

- 必须通过显式重置路径丢弃现有的实验状态。
- 初始产品仍将优先支持 Linux，仅支持 Markdown/CommonMark/GFM、GitHub 和 CLI。
- 架构迁移和提示词资源是仅追加/版本化的发布输入，必须像代码一样接受审查。
- SQLite 仍是部署本地的权威数据源；托管持久化需要单独受保护的状态引用协议，而非缓存。

## 被拒绝的替代方案

- **保留外部技能作为兼容性适配器：** 已否决，因为这会保留两个权威来源以及无法复现的运行时依赖项。
- **导入旧的 JSON/JSONL 或实验性 SQLite 状态：** 已拒绝，因为 fani 尚未发布，而迁移会固化不稳定的语义。
- **让智能体编辑代码仓库：** 已拒绝，因为无法信任模型输出对路径、状态或发布作出决策。
- **立即创建多 crate 工作区或通用插件运行时：** 已拒绝，因为目前不存在独立版本化的构件或第二个生产环境前端。
- **使用可变工作树内容作为源计划：** 已拒绝，因为源身份识别和发布容易出现竞态条件。

## 强制执行

当前有效的契约详见 [`native-i18n.md`](native-i18n.md)。架构测试强制保证依赖方向及由应用程序拥有的粗粒度端口。集成测试使用真实的临时 SQLite 数据库、Git 仓库、提供程序进程、物化过程和 GitHub 命令固件。CI 使用 `--locked` 进行构建，检查与 Rust 1.85 的兼容性，并且不会安装或调用已被取代的 Python/skill 运行时。

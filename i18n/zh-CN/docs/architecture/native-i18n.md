# 原生 i18n 架构

日期：2026-08-30\
状态：fani 0.3 的实现契约\
决策记录：[`ADR-0001`](adr-0001-native-single-authority.md)

## 产品边界

fani 0.3 是一款面向 GitHub 仓库、优先支持 Linux 的持续文档翻译命令行工具。它支持 Markdown/CommonMark/GFM、内置 HTTPS 模型提供商、严格的自定义命令 Agent 协议、SQLite 状态管理、Git 分支发布以及 GitHub 拉取请求。本版本不涵盖 MDX、资源文件、其他代码托管平台、自动合并、Web UI，也不兼容实验性的 Python/i18n-skill 实现。

## 权威

- 每个源计划均以固定的 Git 提交为准。
- 位于 `<repo>/<data_dir>/fani.db` 的单个 SQLite 数据库是所有归 fani 所有的文档、单元、翻译记忆、工作、审核、恢复和发布记录的权威数据源。
- 代理输出是不受信任的候选文本。
- 目标译文只有在经过合并协调或明确验证并采用后，才会成为可信记忆。
- 报告是可替换的视图。提示词和迁移是嵌入式资源。二者都不是第二状态权威源。

任何运行时路径都不会调用外部 i18n skill、Python 或 `uv`。不会导入旧的 JSON、JSONL、lock 或 SQLite 格式。

## 命令契约

|命令|副作用|含义|
| --- | --- | --- |
| `fani init` |以原子方式创建经过验证的配置；除非指定 `--force`，否则拒绝覆盖|为内置提供商创建一个保守的、仅限本地使用的初始配置。|
| `fani doctor` |仅在严格验证配置后，才可创建或打开已配置的 SQLite 数据库|验证配置、Git 仓库、内置提供商凭据或自定义 Agent 命令、SQLite，以及可选的 GitHub 先决条件。|
| `fani status` |对仓库和智能体仅具有只读权限|基于不可变的源修订版制定计划，并报告待处理、复用及冲突的工作。|
| `fani check` |对存储库和智能体为只读权限|确定性规划/检查路径的别名，用于提高 CI 的可读性。|
| `fani sync` |持久化 SQLite 工作、有界的 Agent 调用、经验证的物化/发布|继续或执行翻译工作。|
| `fani adopt` |确定性验证后的持久协调|将经过验证的人工编辑目标文本作为规范内容和可信翻译记忆库。|
| `fani discard` |持久协调|放弃有分歧的人工编辑，并恢复经过验证的规范目标。|

稳定的进程结果为 `0 ok`、`1 needs_human`、`2 error` 和 `3 partial`。配置在每个表上都使用 `serde(deny_unknown_fields)`，并在产生任何数据库、仓库、Agent、Git 或 GitHub 副作用之前完成全面解析和验证。

## 原生文档处理

1. 将 `publish.source_ref` 解析为一个提交 SHA。
2. 使用 `git ls-tree` 查找已配置的 Markdown Blob；从该 SHA 读取每个 Blob，绝不要从可变工作树中读取。
3. 使用 `pulldown-cmark` 偏移事件进行解析，并派生稳定的文档/单元标识。
4. 保护代码、链接目标、HTML、占位符和不可翻译的前置元数据范围。
5. 在调用智能体之前，仅复用完全匹配的可信翻译记忆。模糊匹配结果仅用于提供上下文或确定性冲突；绝不会被静默发布。
6. 使用按字节范围降序的替换方式进行组装。空替换保持字节完全相同；所选范围之外的字节保持完全相同。
7. 验证令牌标识、范围有效性、Markdown 结构以及已配置的项目检查。
8. 在具体化或发布之前，持久化规范的目标字节。

## SQLite 契约

0.3 版本的架构被刻意设计为破坏性架构。使用不受支持的应用程序 ID 或架构版本打开文件时，操作会失败并提供重置指导；不会执行兼容性迁移。

该模型涵盖代码仓库和语言、源修订版本、文档和单元出现记录、翻译版本和可信记忆库、运行和工作项、已完成的尝试、发现和转换、规范候选数据块、物化/发布发件箱、拉取请求生命周期以及可续租约。

连接策略为 `foreign_keys=ON`、回滚日志、`synchronous=FULL`，以及有界的忙碌超时。事务仅包含本地状态转换。代理、文件系统、Git 和网络操作在持久化意图提交之后、简短的完成事务之前执行。

## 智能体边界

提供方接收一个由嵌入式版本化提示渲染的类型化任务。它在一个空的临时工作目录中运行，并使用临时的 `HOME`、明确的环境变量允许列表、大小受限的 stdin/stdout/stderr/结果文件、绝对截止时间、进程组 TERM/KILL 升级机制和后代进程清理机制，且无法访问仓库路径。fani 会验证返回的文本，并自行执行所有文件、数据库和发布操作。

## Git 和 GitHub 发布

候选树从固定的源提交开始，并使用临时索引按照类型化的允许列表应用目标的添加、修改和删除变更。`commit-tree` 创建候选提交；本地引用使用比较并交换，远程更新使用带租约的强制推送。候选构建绝不会更改或发布已检出的分支、`HEAD`、真实索引字节/暂存区、无关的工作树文件、数据库、提示、响应、报告和工作文件。

推送和拉取请求操作具有持久的幂等键和协调机制。每个仓库/语言组合都有一个稳定分支和一个开放的拉取请求。对于不确定是否已送达的操作，会先查询再重试。合并协调会记录观察到的 GitHub 元数据，并且是将已合并翻译提升至可信记忆的常规路径。

## 模块方向

项目仍是单个 Cargo 包和模块化单体。`main` 将任务委托给 `cli`；命令处理程序组合应用操作；纯 Markdown/领域函数不依赖 SQLite、GitHub 或子进程；适配器实现粗粒度状态、Agent、物化、Git 和代码托管边界。仅当存在单独进行版本控制/发布的构件时，才会重新考虑采用工作区。

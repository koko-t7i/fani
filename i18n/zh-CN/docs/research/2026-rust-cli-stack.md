# 原生 Rust CLI 技术栈决策

**状态：** 已实现，并自 2026-08-30 起取代实验性预发布架构。

## 决策

fani 是一款优先支持 Linux 的 Rust 2024 命令行应用程序，最低支持的工具链版本为 Rust 1.85。它使用：

- `clap` 用于命令行界面。
- `serde`、`serde_json` 和 `toml`，用于严格类型化的配置、Agent 信封、持久化载荷和报告。
- `pulldown-cmark`、`regex`、`globset` 和 `strsim`，用于原生 Markdown 提取、受保护语法、源文件发现和确定性单元匹配。
- 将捆绑的 `rusqlite` 作为由 fani 独有并统一管理运行、工作、尝试、发现、规范内容、可信翻译记忆库、租约、发件箱和拉取请求状态的权威数据源。
- 为内置模型提供商提供同步且有界的 HTTPS 适配器，为自定义 Agent 提供严格的子进程适配器，并为 Git 和 GitHub 操作提供子进程适配器。每个外部边界都有明确的截止时间和受限的输入/输出；自定义 Agent 进程还使用受控的环境变量和 Linux 进程树清理机制。
- 使用临时索引的 Git 底层命令，用于创建固定来源的候选提交，而不更改当前检出的分支、`HEAD`、实际索引、暂存区或工作树中无关的文件。
- `gh` 用于受限的 GitHub 拉取请求创建与协调。

## 被否决的运行时架构

已发布的应用程序不会调用外部本地化技能，不需要脚本语言运行时或软件包运行器，不会将权威数据分散到 JSON 文件和 SQLite 中，也不会导入旧版状态或迁移实验性架构。我们有意不支持这些预发布阶段的做法。

该应用程序也不使用异步运行时。其基于有限线程的子进程和 I/O 模型足以满足配置的本地并发需求，同时可缩短 SQLite 事务并明确副作用边界。

## 原理

原生设计使 Markdown 的规划、匹配、组装和确定性验证均可独立测试。SQLite 为本地状态提供事务性标识与恢复机制，而持久化发件箱则涵盖无法参与数据库事务的文件系统、Git 和 GitHub 操作。稳定的源修订版本和比较并交换发布机制可防止并发的源或分支变动被悄然接受。
